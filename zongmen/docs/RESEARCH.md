## 1. 引擎仓库和文档

- “天工引擎”就是 **ForgeaX Engine**，npm 包 `@forgeax/engine`。
  - 最新稳定版 **0.4.19**（2026-11-06 发布），测试版 `0.5.0-rc.1`，开发版 `0.6.0-dev.*`。
  - 开源协议 **Apache-2.0**，允许商用和修改，需保留版权与许可声明。
  - 源码在 GitHub 的 `ForgeaXGame` 组织下（包内文档链接到 `ForgeaXGame/forgeax-engine-harness`）。
- 文档随包分发：包内 `README.md`，以及新建工程后复制进来的 `AGENTS.md` 和 `skills/forgeax-engine-*`（20 多个技能文档）。教程在 <https://forgeax.github.io/zh/tutorials/>。
- 一张包里带了渲染（WebGPU）、ECS、物理（Rapier）、UI、音频、NPC、Intelligence（模型调用抽象）等全部能力，按子路径引入，如 `@forgeax/engine/npc`。
- 本仓库之前的两个游戏（寒驿、青冥录，见仓库根目录）已经跑在 0.4.8 上，在这类无显卡的 Linux 沙箱里要用 Xvfb + SwiftShader 软件渲染才能预览（见 `../../tiangong/docs/feedback.md`）。

出处：`npm view @forgeax/engine`；包内 `README.md`；[17173：天工引擎开源](https://news.17173.com/content/11032026/120358043.shtml)。

## 2. 在 Claude Code 里装造化插件

- 造化插件对应 npm 包 **`@forgeax/game` 0.4.2**（MIT），绑定引擎 SDK 0.4.8。README 里的安装命令是：

  ```bash
  npx -y @forgeax/game install --ide codex,cursor,claude   # 给 Agent 装 MCP 和技能
  cd 空目录 && npx -y @forgeax/game init                    # 建工程
  ```

  也就是说 **Claude Code 是官方支持的 Agent 环境**（报道里没提到，但包里写了）。
- 插件提供的 MCP 工具：`forgeax_run_current_game`（构建并本地预览）、`forgeax_game_read_file` / `write_file` / `list_files` / `read_logs`、`forgeax_status_lite`、`forgeax_view_start`、`forgeax_generate_image`，以及扩展（音频、3D 角色生成、场景生成、叙事、特效）。
- **没找到“作品上传与排行榜”的命令或工具**：0.4.2 的插件只管本地开发。发布大概率是在造化工坊网站上上传（官网文案有“一键发布”“下载完整项目，一键构建，随处部署”），需要登录后确认。
- 本次会话里运行 `npx @forgeax/game init` 被沙箱的权限检查拦下，所以**没有在这里跑通官方示例的本地预览**。文档的“需要用户本人做的事”第一条（在自己电脑上运行 Claude Code）正好覆盖这一步。

## 3. 运行时调用大模型（阻断）

查到的情况：

- 引擎的 `@forgeax/engine-intelligence` 是**与提供方无关的抽象**：游戏提交 Activity、每帧轮询结果；“提供方 SDK、密钥和子进程都归 Host 所有”。它本身不提供模型服务。
- 引擎自带的 DeepSeek 适配器 `@forgeax/engine-intelligence-dsh` 要在本机启动一个 `dsh-jsonrpc-agent` 进程，只适合本地/桌面，**不能用在发布到网页和 App 的游戏里**。
- 插件里出现的 `https://llm-proxy.forgeax.com/v1` 是一个 LiteLLM 网关，只被创作期的音频、3D 生成扩展使用，用的是创作者自己的凭据，不是给发布后的游戏用的。
- 造化工坊官网前端的文案里有“AI 原生引擎：运行时游戏生成，AI 对话，AI 代理机器人”“LLM Chat 积分明细”“模型配置 / 添加自定义 API（API 提供商、密钥）”。说明平台**有**模型能力，但创作工具里还能配“自定义 API 密钥”，没有公开文档说明：发布后的游戏能不能调用、用什么模型、费用由谁出（玩家的灵感点？作者的积分？）、频率限制和内容审核。

按文档的决策：

- A（平台提供模型服务）：**没有证据证明可用，也没有接口文档**。
- B（只能自带 API Key）：不能把 Key 打进客户端，需要用户的云账号搭代理。
- C（不支持）：也没有证据。

**需要用户做的**：登录造化工坊或在官方 QQ 群里问清“发布的游戏运行时怎么调用大模型”，把文档或截图发给我；或者决定走 B（提供一个云账号，我来写代理服务）。

在此之前的处理：游戏代码只依赖统一的 `AIClient` 接口，三种实现（平台、经代理的 OpenAI 兼容接口、模板应答）在 `config/game.json` 里切换；模板应答模式已能完整打通一局，所以无论哪种结论，逻辑层都不用改。

### 单局用量估算

按 `src/ai/prompt.ts` 的保守估算（中文 1 字算 1 token）：

| 项目 | 估算 |
| --- | --- |
| 系统提示词（人设 + 知识卡 + 规则 + 格式） | 约 1,100–1,400 token（其中人设加知识卡 330–620），同一局同一弟子不变，可命中前缀缓存 |
| 每轮输入（含最近 8 轮历史） | 约 1,300–2,400 token |
| 每轮输出 | 约 60–150 token |
| 单局 30 次问话 + 1 次尾声（不含重新生成） | 输入约 5–6 万 token（其中大半可缓存），输出约 3–4 千 token |

模型定下来后，按它的实际单价算出单局成本补在这里。

## 4. 界面能力

- 插件的规则要求界面挂在引擎 Host 提供的 `uiRoot` 或 `#game-ui` 上，禁止直接改 `document.body`。之前的寒驿、青冥录都是这样做的 HTML 界面，叠在引擎画布上。
- 因为是普通 HTML `<input>`，浏览器和手机输入法的中文输入都可用；滚动列表、头像（CSS 或画布绘制）都没有障碍。
- **造化工坊 App 里的表现未验证**（需要发布后在 App 里试）。降级方案已实现：3 个快捷问题 + “问某人的事”（`src/game/quick.ts`）。

## 6. 内容合规

- 引擎和插件里没有内容审核接口，官网前端也没看到给游戏用的审核 API。
- 已按文档第 7 节做基础过滤：玩家输入过 `data/blocklist.json`（命中就不调用模型、回兜底台词）；模型输出过 `data/leak_patterns.json`（认罪措辞、出戏字样）。平台若提供审核接口，在 `GameSession.isBlocked` 和输出校验里接上即可。
